# tts-benchmark

Benchmarks text-to-speech inference time and model footprint on the **Arduino UNO Q**. The target is the board's Qualcomm QRB2210 Linux side (quad-core ARM Cortex-A53), so real timings should be collected on the board rather than on a laptop or cloud GPU. Audio quality is outside the scope of this benchmark.

The project currently compares **18 ONNX voices**:

- 3 VITS models exported from Hugging Face: MMS-TTS English, VITS LJSpeech, and VITS VCTK low.
- 15 Piper voices: Lessac, Ryan, Amy, Alan, and Cori, each in low, medium, and high quality variants.

All entries are defined in [`models_config.json`](models_config.json). The benchmark uses ONNX Runtime on CPU for the VITS exports and Piper's ONNX runtime for Piper voices.

## Quickstart

The base dependencies are enough to generate synthetic sample data and render a report. No model weights or PyTorch are needed:

```powershell
uv run visualize.py
```

To regenerate the synthetic data for every configured model, then render it:

```powershell
uv run simulate.py
uv run visualize.py
```

Synthetic timings are engineering estimates for a weak quad-core Cortex-A53, not measurements. They are useful for checking the pipeline and chart, but must not be presented as board results.

## Run the real benchmark

Install the real-model dependencies and run on the UNO Q itself:

```powershell
uv sync --extra real
uv run benchmark.py
uv run visualize.py
```

The benchmark supports:

```text
--runs N                 Timed runs per model (default: 9)
--warmup N               Untimed warmup runs per model (default: 1)
--models slug1,slug2     Comma-separated model slugs (default: all)
--threads N              PyTorch CPU threads (default: all available cores)
```

Examples:

```powershell
uv run benchmark.py --models piper-lessac-low,piper-ryan-medium --runs 3
uv run benchmark.py --models mms-tts-eng-onnx,vits-ljs-onnx --runs 9 --threads 4
```

Each model is loaded once, warmed up, and timed over sentences from [`data/gaudi_sentences.json`](data/gaudi_sentences.json). Runs are round-robin balanced across short (up to 8 words), medium (9-16 words), and long (17+ words) sentences. Generated WAV files are saved under `audios/<model-slug>/`, and the results are written to [`data/inference_results.json`](data/inference_results.json).

For VITS models, `benchmark.py` reads the exported model from `onnx_models/<model-slug>/model.onnx` and loads its tokenizer from the corresponding Hugging Face repository. For Piper models, the ONNX voice and JSON config are downloaded from `rhasspy/piper-voices` into the local Hugging Face cache on first use. Internet access is therefore required the first time each Piper voice is benchmarked.

The script records the detected Linux RAM, CPU thread count, measured or configured disk size, per-run timings, and `fits_2GB_ram` / `fits_4GB_ram` estimates. The UNO Q is available with 2 GB and 4 GB RAM variants. Plain PyTorch/ONNX Runtime execution uses CPU; the meaningful comparison is the timing collected on the board.

## Export the VITS models

The `onnx_models/` directory contains the current VITS exports. To create or replace an export, install the real dependencies and run the wrapper around Optimum:

```powershell
uv sync --extra real
uv run export_onnx.py --model facebook/mms-tts-eng onnx_models/mms-tts-eng-onnx
uv run export_onnx.py --model kakao-enterprise/vits-ljs onnx_models/vits-ljs-onnx
uv run export_onnx.py --model kakao-enterprise/vits-vctk onnx_models/vits-vctk-low-onnx
```

`export_onnx.py` provides a compatibility shim for the project's `torch<=2.3.1` constraint. The export destination must match the slug used by the benchmark configuration, and the directory must contain `model.onnx` plus the tokenizer files required by the model.

## Visualize results

```powershell
uv run visualize.py
uv run visualize.py --results data/inference_results.json --output results/comparison.png
```

The script prints a table and writes [`results/comparison.png`](results/comparison.png). The chart shows median inference time with min/max whiskers for each sentence-length bucket, alongside on-disk model size. The checked-in result data is a real UNO Q run when its metadata says so; data generated by `simulate.py` is explicitly marked as simulated in `benchmark_meta`.

## Repository layout

```text
pyproject.toml / uv.lock       dependencies and lockfile
models_config.json             benchmark model and voice registry
common.py                      length buckets, balanced sampling, RAM-fit helpers
benchmark.py                   real ONNX/Piper benchmark
simulate.py                    synthetic data generator
export_onnx.py                 VITS-to-ONNX export wrapper
visualize.py                   table and comparison chart
data/gaudi_sentences.json      fixed TTS input sentences
data/inference_results.json    benchmark output and metadata
onnx_models/<slug>/             local VITS ONNX exports
audios/<slug>/                 generated WAV files
results/comparison.png         generated chart
```

The base dependency set contains `numpy`, `matplotlib`, and `soundfile`. The `real` optional extra adds PyTorch, Transformers, Hugging Face Hub, datasets, phonemizer, and SentencePiece; the `real` dependency group also supplies ONNX Runtime, Optimum ONNX, and Piper TTS.

## Add a model or voice

1. Add an entry to [`models_config.json`](models_config.json), including a unique `slug`, display `name`, source `model_id`, `architecture`, and `disk_size_mb`.
2. Use `architecture: "vits-onnx"` when the model is a VITS ONNX export under `onnx_models/<slug>/`.
3. Use `architecture: "piper"` and provide `onnx_filename` and `config_filename` when the voice is hosted in a Piper repository.
4. Run `uv run simulate.py` to verify that the new entry is picked up automatically. For a real measurement, run `benchmark.py --models <slug>` on the UNO Q.

The supported special loaders live in `benchmark.py`. An unregistered architecture falls back to the Transformers text-to-speech pipeline, but that path is not used by the current configuration and requires the corresponding model-specific dependencies.
